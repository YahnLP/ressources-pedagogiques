# 🔬 TP – S14 ANNÉE 2 – E2
## Simulation de Pannes : Diagnostic Méthodique + Fiches de Maintenance

---

## 🎯 OBJECTIFS DU TP

- ✅ Appliquer la démarche DECA sur 4 pannes inconnues
- ✅ Choisir les bons instruments et commandes de diagnostic
- ✅ Identifier la cause racine (pas juste les symptômes)
- ✅ Rédiger une fiche de maintenance pour chaque panne résolue
- ✅ Valider la réparation par un test mesurable

---

## ⏱️ DURÉE : 100 min (4 × 25 min de diagnostic par maquette + rotation)

---

## ⚠️ RÈGLES DU TP

```
AVANT toute mesure ou manipulation :
  ☐ Écrire le symptôme observé
  ☐ Lister 3 hypothèses de cause
  ☐ Choisir l'instrument adapté à la première hypothèse

PENDANT le diagnostic :
  ☐ Croiser une hypothèse à la fois (pas de mesures aléatoires)
  ☐ Documenter chaque mesure (valeur obtenue vs valeur attendue)

APRÈS réparation :
  ☐ Test de fonctionnement (le symptôme a disparu ?)
  ☐ Test de régression (les autres fonctions marchent ?)
  ☐ Fiche de maintenance complétée avant de passer à la maquette suivante
```

---

## 📋 MAQUETTE DE RÉFÉRENCE

> Chaque maquette est un ESP32 DevKit avec :
> - Capteur DHT22 (ou BMP280) connecté en I2C
> - LED de statut sur Pin 2
> - Connexion MQTT vers broker local (Mosquitto) ou AWS IoT
> - Code de base affiché dans le moniteur série (115200 bauds)

```
Code de diagnostic intégré (extrait) :

void loop() {
  Serial.println("=== STATUS ===");
  Serial.println("VCC (mesuré) : 5.0V (à vérifier au multimètre)");
  Serial.println("WiFi RSSI : " + String(WiFi.RSSI()) + " dBm");
  Serial.println("MQTT state : " + String(mqtt.state()));
  Serial.println("Heap libre : " + String(ESP.getFreeHeap()) + " bytes");
  Serial.println("Uptime : " + String(millis()/1000) + " s");
  delay(3000);
}
```
